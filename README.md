# iTIC Accident Data Explorer

เว็บแอปสำหรับดึงรายการอุบัติเหตุทางถนนจาก **iTIC Foundation API** (`https://api.iticfoundation.org/accidents`)
พร้อมตัวกรองที่ใช้งานง่าย และส่งออกข้อมูลเป็น CSV (รองรับภาษาไทยใน Excel)

## คุณสมบัติ

- **เข้าสู่ระบบด้วยบัญชี iTIC** — token ถูกเก็บไว้ฝั่งเซิร์ฟเวอร์ (httpOnly cookie) ไม่เก็บในเบราว์เซอร์
- **กรองตามช่วงวันที่** พร้อมปุ่มลัด 7 / 30 / 90 วันล่าสุด, ทั้งปีปัจจุบัน และปีย้อนหลัง 3 ปี
  (ช่วงที่เลือกได้ = **2022-01-01 ถึงวันนี้** และปรับ `max` ของช่องวันที่อัตโนมัติทุกครั้งที่เปิดหน้า)
- **แผนที่อุบัติเหตุ (Leaflet + CARTO basemaps)** — หมุดสีตามความรุนแรง, วงแหวนจุดเสี่ยง,
  หมุดเหตุการณ์ปัจจุบัน, **ลากหมุด/คลิกบนแผนที่เพื่อค้นหาใหม่** และปุ่ม "ดูผลลัพธ์ทั้งหมด"
- **โหมดมืด / สว่าง** — สลับได้จากปุ่มบนแถบหัวเรื่อง (จำค่าไว้ใน `localStorage`) และสลับชุดแผนที่ตามธีม
- **แผงจุดเสี่ยง (Blackspot)** — เลือกชุดข้อมูล (cluster), พื้นที่ (จังหวัด/อำเภอของจุดที่ค้น) และเกณฑ์เรียง
  แสดงอันดับ/จำนวนอุบัติเหตุ/เสียชีวิต/บาดเจ็บ/ระดับความรุนแรง คลิกแถวเพื่อซูมไปยังจุดนั้นบนแผนที่
- **เลือกประเภทข้อมูลได้**
  - แหล่งข้อมูล: **ทั้งหมด (รวมทุกแหล่ง)** / RAIS / RVP / iTIC
  - ระดับความรุนแรง: ทั้งหมด / มีผู้บาดเจ็บ / มีผู้เสียชีวิต
  - ประเภทยานพาหนะ (กรองฝั่งหน้าเว็บ จากผลลัพธ์ที่ดึงมา)
- **เลือกจังหวัดจากรายการ** 77 จังหวัด ตามรหัส geocode กรมการปกครอง (อ่านจาก `data/provinces.csv`)
- **คำค้น** ตามรายละเอียดอุบัติเหตุ
- **จำกัดพื้นที่** (point + buffer) พร้อมพิกัดและรัศมีเป็นเมตร
- **ระบุชื่อบริเวณอัตโนมัติ** เมื่อค้นหาด้วยพิกัด — แสดงชื่อถนน/จุดเสี่ยง, แขวง/ตำบล, เขต/อำเภอ, จังหวัด
  และจำนวนอุบัติเหตุในพื้นที่ พร้อมค้นหาสถานที่ด้วยชื่อ (เช่น `แยกสุทธิสาร`) เพื่อเติมพิกัดให้อัตโนมัติ
  และการ์ดสรุปในรัศมี (จำนวนอุบัติเหตุ/เสียชีวิต/บาดเจ็บ ตามช่วงวันที่ที่เลือก) พร้อมอันดับของอำเภอในจังหวัด
- **เหตุการณ์จราจรปัจจุบัน (Longdo Map)** — แสดงเหตุการณ์สดใกล้พื้นที่ที่ค้นหา (น้ำท่วม, ปิดถนน, เบี่ยงจราจร,
  เพลิงไหม้ ฯลฯ) พร้อมระยะทางและเวลา และส่งออก CSV ได้
- **ดึงข้อมูลทั้งหมดอัตโนมัติ** (แบ่งหน้าละ 2,000 รายการจนครบ)
- **ตารางผลลัพธ์** เรียงลำดับได้, แบ่งหน้า, คลิกแถวเพื่อดูรายละเอียดยานพาหนะ/ผู้ประสบเหตุ
- **ส่งออก CSV 2 รูปแบบ**
  - `ส่งออก CSV` — 1 แถวต่อ 1 อุบัติเหตุ (มีคอลัมน์แหล่งข้อมูลของแต่ละแถว)
  - `CSV รายละเอียดผู้ประสบเหตุ` — 1 แถวต่อ 1 ผู้ประสบเหตุ (แยกตามยานพาหนะ)

## สิ่งที่ต้องมี

- Node.js 18 ขึ้นไป (ใช้ `fetch` และ `AbortSignal.timeout` ที่มีในตัว)
- ไม่ต้องติดตั้ง dependency ใด ๆ

## วิธีใช้งาน

```bash
npm start
```

แล้วเปิด <http://127.0.0.1:3000>

โหมดพัฒนา (รีสตาร์ทเซิร์ฟเวอร์อัตโนมัติเมื่อแก้ไฟล์):

```bash
npm run dev
```

จากนั้นเข้าสู่ระบบด้วยบัญชี iTIC ที่ได้รับมา แล้วกำหนดเงื่อนไข → กด **ค้นหาข้อมูล** → **ส่งออก CSV**

## การตั้งค่า

คัดลอก `.env.example` เป็น `.env` แล้วปรับค่า:

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
| --- | --- | --- |
| `PORT` | `3000` | พอร์ตของเว็บแอป |
| `HOST` | `127.0.0.1` | ใช้ `0.0.0.0` หากต้องการให้เครื่องอื่นในเครือข่ายเข้าถึง |
| `API_BASE` | `https://api.iticfoundation.org/accidents` | ปลายทาง API |
| `SESSION_TTL_MS` | `28800000` (8 ชม.) | อายุเซสชันฝั่งเซิร์ฟเวอร์ |

## โครงสร้างโปรเจกต์

```
server.js          เซิร์ฟเวอร์ HTTP (ไม่มี dependency) + proxy ไปยัง iTIC API + จัดการเซสชัน
data/provinces.csv รหัส geocode จังหวัด 77 รายการ (Code,Province_TH,Province_EN)
public/index.html  หน้าจอ UI
public/styles.css  ธีม (สว่าง/มืด)/เลย์เอาต์/แผนที่
public/app.js      ตรรกะการค้นหา, ตาราง, แผนที่, จุดเสี่ยง, CSV
public/vendor/leaflet/  Leaflet 1.9.4 (JS/CSS/ไอคอน) ที่ vendor ไว้ใช้แบบออฟไลน์
```

ต้องการอัปเดตรายชื่อจังหวัด/รหัส geocode ให้แก้ที่ `data/provinces.csv` แล้วรีสตาร์ทเซิร์ฟเวอร์
(แอปอ่านไฟล์นี้ผ่าน `GET /api/provinces` ไม่ต้องแก้โค้ด)

## API ที่ใช้งาน

| Endpoint | ใช้ทำอะไร |
| --- | --- |
| `POST /auth/login` | รับ access token (form-urlencoded: `user`, `pass`) |
| `POST /get_list` | ค้นหารายการอุบัติเหตุ (JSON body) |
| `GET /blackspot/get_list` | รายการจุดเสี่ยง (blackspot) ตาม cluster/พื้นที่/เกณฑ์เรียง |
| `GET /blackspot/get_by_area` | ชื่อจุดเสี่ยง/ถนน บริเวณพิกัดที่กำหนด (ใช้ตั้งชื่อบริเวณ) |
| `GET /get_by_district` | ชื่อเขต/อำเภอ/จังหวัด + สถิติ/อันดับ/ระดับของอำเภอ (ใช้ตั้งชื่อบริเวณและสรุปพื้นที่) |
| `GET /get_summary_by_area` | สรุปจำนวนอุบัติเหตุ/เสียชีวิต/บาดเจ็บในรัศมี (ข้อมูล RAIS) |
| `GET /cluster/get_list` | ชุดข้อมูลวิเคราะห์จุดเสี่ยง (cluster) และเกณฑ์เรียงที่รองรับ |

แอปมี endpoint ภายในของตัวเองด้วย: `POST /api/login`, `POST /api/logout`, `GET /api/session`,
`GET /api/provinces`, `POST /api/accidents`, `GET /api/area`, `GET /api/geocode`, `GET /api/events`,
`GET /api/clusters`, `GET /api/blackspots`, `GET /api/district-stats`, `GET /api/area-summary`

### แผนที่และจุดเสี่ยง

- ใช้ **Leaflet 1.9.4** (vendor ไว้ใน `public/vendor/leaflet/`) และ **CARTO Basemaps**
  (`voyager` สำหรับธีมสว่าง, `dark_all` สำหรับธีมมืด) ด้วยคีย์ที่ตั้งไว้ใน `public/app.js`
- แผนที่วาดได้สูงสุด 4,000 จุดต่อครั้ง (เรียงให้จุดที่มีผู้เสียชีวิตอยู่บนสุด) เพื่อความเร็ว
- **ลากหมุด** หรือ **คลิกบนแผนที่** = ย้ายจุดค้นหาและค้นหาใหม่ทันที (อัปเดตช่อง lat/lon ให้ด้วย)
- **ระดับสีของจุดเสี่ยง** (แดง/เหลือง/เขียว) แอปเป็นผู้คำนวณจาก **อันดับ (rank)** ในรายการที่กรองอยู่
  (10 อันดับแรก = มาก, 50 อันดับแรก = ปานกลาง, ที่เหลือ = น้อย) เพราะ `blackspot/get_list` ไม่ได้ส่งระดับมาให้
  — ไม่ใช่ค่าจาก API
- cluster ที่ตรงกับช่วงวันที่ค้นหาจะถูกเลือกให้อัตโนมัติ ถ้าไม่มีชุดข้อมูลที่ทับซ้อน จะขึ้นคำเตือน
  "⚠ ชุดข้อมูลครอบคลุม …" ไว้ใต้หัวข้อ

> **เลือก "ทั้งหมด"** แอปจะยิงคำขอแยกทีละแหล่ง (RAIS → RVP → iTIC) แล้วรวมผลลัพธ์ให้
> โดยติดป้ายแหล่งข้อมูลรายแถว จึงใช้เวลานานกว่าการเลือกแหล่งเดียวประมาณ 3 เท่า

### การตั้งชื่อบริเวณ (Area naming)

เมื่อค้นหาด้วยพิกัด แอปจะเรียก 2 แหล่งพร้อมกันแล้วเลือกชื่อที่เหมาะสมที่สุด:

1. **iTIC** — `blackspot/get_by_area` (ชื่อถนน/จุดเสี่ยง + จุดสังเกต) และ `get_by_district` (เขต/อำเภอ/จังหวัด)
2. **OpenStreetMap (Nominatim)** — reverse geocoding สำหรับชื่อแยก/ถนน/แขวง
   - ใช้เมื่อผู้ใช้กด "ค้นหา" สถานที่ในช่องค้นหาสถานที่ (เช่น `แยกสุทธิสาร`)
   - มีการจำกัดความถี่ ~1 คำขอ/วินาที และแคชผล 10 นาที ตามนโยบายของ Nominatim
   - ต้องต่ออินเทอร์เน็ต; ถ้าเรียกไม่สำเร็จ การ์ดบริเวณจะยังแสดงข้อมูลจาก iTIC ตามปกติ

### เหตุการณ์จราจรปัจจุบัน (Longdo Map)

การ์ด **"เหตุการณ์ปัจจุบัน"** ใช้ข้อมูลจาก <https://event.longdo.com/feed/json> ซึ่งเป็น feed
เหตุการณ์จราจรสดของ Longdo Map (ไม่ต้องใช้ API key)

- ถ้าค้นหาด้วยพิกัด → แสดงเหตุการณ์ภายในรัศมี **5 กม.** (หรือมากกว่าถ้ารัศมีที่กรอกใหญ่กว่า) พร้อมระยะทาง
- ถ้าไม่ได้ระบุพิกัด → ใช้กรอบพื้นที่ (bounding box) ของผลค้นหาอุบัติเหตุ
- ประเภทที่รองรับ: น้ำท่วม, เพลิงไหม้, อุบัติเหตุ, ปิดถนน, เบี่ยงจราจร, รถเสีย, แผ่นดินไหว, กิจกรรม/พิธี
- แคชฝั่งเซิร์ฟเวอร์ **60 วินาที**, ตัดรายการซ้ำ (feed มีหลาย entry ต่อเหตุการณ์เดียว)
- ส่งออกได้ด้วยปุ่ม `ส่งออก CSV` ในการ์ด → ไฟล์ `longdo_events_YYYY-MM-DD.csv`

> ⚠️ **ข้อจำกัด**
> - เป็น **snapshot ของเหตุการณ์ที่ยังเปิดอยู่** ไม่ใช่ข้อมูลย้อนหลัง จึงใช้แทนสถิติอุบัติเหตุไม่ได้
> - feed ไม่ได้ระบุ license อย่างชัดเจน — ใช้เพื่อการอ้างอิงภายในเท่านั้น และควรแสดงเครดิต **Longdo Map**
> - บางรายการเป็นเหตุการณ์ระยะยาว (เช่น ปิดเบี่ยงจราจรงานก่อสร้าง) เวลาสิ้นสุดอาจอยู่ในอนาคตหลายปี
> - ข้อมูลอาจซ้ำหรือมีรายละเอียดไม่ครบถ้วน ขึ้นอยู่กับผู้ให้ข้อมูลแต่ละราย

เอกสารเต็ม: <https://api.iticfoundation.org/>

## ข้อจำกัดที่ควรทราบ

- **ช่วงข้อมูลที่มีจริง: 2022-01-01 ถึงวันนี้** (ตรวจสอบล่าสุด: มีข้อมูลถึง พ.ย. 2026 และยังไม่มีข้อมูลปี 2027)
  - ปี 2019–2021 มีข้อมูลน้อยมาก (หลักสิบ–หลักร้อยรายการ) จึงไม่เปิดให้เลือกใน UI
  - ช่วงที่เลือกได้ในหน้าเว็บปรับ `max` เป็น "วันนี้" อัตโนมัติ ไม่ต้องแก้โค้ดเมื่อขึ้นปีใหม่
- **ชุดข้อมูลจุดเสี่ยง (cluster) ของ API ยังไม่ครบทุกปี** — ปัจจุบันมีปี 2567, 2568 และสงกรานต์ 2568/2569
  ถ้าค้นหาช่วงที่ไม่มี cluster รองรับ แผงจุดเสี่ยงจะแสดงชุดข้อมูลที่ใกล้ที่สุดพร้อมคำเตือน
- ต่อ 1 คำขอ ดึงได้สูงสุด **2,000 รายการ** — แอปจะวนขอเพิ่มจนครบ (สูงสุด 100,000 รายการต่อการค้นหา)
- การค้นหาช่วงยาวมาก (เช่น ทั้งปีทั้งประเทศ) อาจใช้เวลาหลายสิบวินาที กด **ยกเลิก** ได้ระหว่างดึงข้อมูล
- แหล่งข้อมูล **iTIC** ไม่ส่งจำนวนผู้เสียชีวิต/บาดเจ็บมา (เป็น 0 ทุกแถว) จุดบนแผนที่จึงเป็นสีฟ้า
  ("ไม่มี/ไม่ระบุ") — ใช้ RAIS หรือ RVP หากต้องการดูความรุนแรง
- แผนที่ใช้คีย์ CARTO สาธารณะที่ให้มา; หากโดนจำกัดโควตาหรือเปลี่ยนคีย์ ให้แก้ `CARTO_KEY` ใน `public/app.js`

## ความปลอดภัย

- ชื่อผู้ใช้/รหัสผ่านถูกส่งผ่านเซิร์ฟเวอร์ของแอปเท่านั้น ไม่ถูกบันทึกในไฟล์หรือ localStorage
- access token เก็บในหน่วยความจำของเซิร์ฟเวอร์ และผูกกับ cookie แบบ `HttpOnly; SameSite=Lax`
- ค่าเริ่มต้นให้เข้าถึงได้เฉพาะเครื่องตัวเอง (`127.0.0.1`) หากเปิดให้เครื่องอื่นใช้ ควรวางหลัง reverse proxy ที่มี HTTPS
